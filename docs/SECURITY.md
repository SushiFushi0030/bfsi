# 公开发布与本地数据边界

仓库的演示评论、视频信息、Comment ID 和截图全部使用合成内容。它们用于复现工程流程，不代表真实 B站用户观点或模型测评结果。真实运行产生的评论、用户提及、视频解析响应、模型输入输出和 Codex 执行日志只应留在本地。

## 什么可以提交

- `src/`、`web/src/`、配置和运行脚本；经过检查的 Schema 与 Prompt。
- `examples/` 中明确标注为 synthetic 的数据，以及由这些数据生成的展示截图。
- 不含真实账号或历史生产数据的测试 fixture。

## 什么不进入仓库

`var/`、`runs/`、`evidence/`、采集原件、原始模型响应、请求和执行记录、`.env`、Cookie、令牌、CLI 登录目录、浏览器抓包、缓存、虚拟环境、`node_modules/`、构建目录及备份包。`.gitignore` 只是防止误添加；已经被 Git 跟踪的文件不会因此自动移除。

Standard Schema 会剔除专门的账号资料字段，但保留原始评论文字、关系编号及必要上下文；文字里仍可能包含姓名、账号提及或其他个人信息，因此标准化数据**不等于**可公开匿名数据。只替换 Comment ID 也不足以匿名化原文。

## 提交前检查

在仓库根目录运行：

```sh
python3 scripts/check_public.py
git status --short
git diff --cached --stat
git diff --cached
```

扫描器无需联网或第三方依赖。它检查工作文件，并在当前目录已初始化 Git 时检查整个索引内的文件内容，包括已经暂存而工作文件后来被改掉的版本；发现问题返回非零状态。输出仅包含相对路径、行号和风险类别，避免再次泄露命中值。

默认跳过本地环境和生成目录；如果其中的文件已经加入 Git 索引，仍会报警。规则包括个人绝对路径、疑似硬编码凭证、PEM 私钥、受限文件名、运行数据目录和超过 5 MiB 的文件。正常的字段名 `cookie`、`token`、`comment_id` 本身不会触发凭证告警。

它不能判断一句评论是否来自真人，不能完整识别所有密钥格式，也不分析图片像素、二进制内部内容或历史提交。发布前须查看截图、示例来源和实际暂存内容；已有提交历史需要另行检查。规则通过只表示这些启发式检查未发现问题。

## 运行与分享

服务默认只供本机使用，不应直接暴露到公网。评论采集会受平台权限、分页可见性、限速和风控影响；遇到限制应暂停并通过正常访问条件恢复。语义分析会把评论与其上下文提交给配置的模型服务，使用者应在自己的访问权限和数据用途范围内运行。

结果图会包含当前任务的代表评论片段，导出图片不代表已完成隐私审查。对外展示时优先使用仓库合成演示；真实结果由使用者自行检查后决定是否分享。

如果凭证已经提交或上传，先撤销或轮换对应凭证，再清理文件和历史；删除当前文件不能使旧提交中的秘密失效。不要在公开 Issue 中粘贴原始日志或凭证。
